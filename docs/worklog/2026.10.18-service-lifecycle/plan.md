## Pitfalls

- Проверять TCC через службу, запущенную launchd, а не из терминала: ответственность различается.
- Успешный выход screencapture и наличие PNG не доказывают доступ к содержимому окон.
- Accessibility и Screen Recording могут показывать разные имена одного продукта.
- Не сбрасывать разрешения целиком. Старую node-запись удалять после проверки новой.
- HTTP 401 в предыдущем исследовании был вызван опечаткой токена, не сетью.

## Границы

Токены пока не менять по просьбе пользователя. Новую версию не публиковать до проверки.

## Реализация и проверки 0.7.18

- Node/Python записывают plist атомарно; отдельное одноразовое задание launchd через
  `submit` выполняет enable → bootout → bootstrap с ограниченными повторами.
  Ошибка постановки не выдаётся за успех. Задание удаляет себя; результат и ошибки сохраняются.

- На Mac установлен локальный npm-архив 0.7.18; ProgramArguments указывают на
  `~/.local/lib/node_modules/arena-bridge/bin/arena-bridge.mjs`, не Documents/ab-pkg.
- Старый helper оставил осиротевший Node. Выполнена однократная адресная миграция,
  без массового завершения Node/ngrok. После исправления повторная переустановка через
  работающий мост автоматически восстановила туннель, оставила одну пару helper → Node.
- GUI запущен; /health сообщает 0.7.18. Node/Python основные наборы и новые тесты службы — PASS.
- Подписи проверяются строго, ошибки сборки больше не подавляются; архитектура helper проверяется
